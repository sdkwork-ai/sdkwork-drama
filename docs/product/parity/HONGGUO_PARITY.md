# 红果短剧功能对齐与商业化就绪度审计（2026-11）

- 状态：审计结论（🔒 需要产品/架构评审后再进入契约变更）
- 对象：`sdkwork-drama` 当前实现 vs 红果免费短剧公开功能基线
- 目的：回答两个问题——(1) 当前实现与红果是否"完整一致"；(2) 距离商业化落地还差什么
- 依据：仓库代码/契约优先（`apis/`、`crates/`、`apps/`、`specs/`），红果功能来自公开资料（文末引用）
- 审计日期：2026-11-13

## 1. 结论摘要

| 问题 | 结论 |
| --- | --- |
| 与红果是否完整一致 | **否**。当前是创作者工作台（剧集 CRUD/发布/媒体上传），红果是消费级短剧平台（发现/播放/追剧/变现）。消费侧 P0 能力尚未实现 |
| 已实现部分是否有回归 | **无回归**。作者侧功能在本次审计中类型检查、单测、构建与 15 项仓库门禁均通过（见 §6） |
| 能否直接商业化落地 | **不能**。缺内容模型、公开目录/搜索/榜单、可播放地址与播放器、进度/收藏/历史、广告变现、审核与合规、统计推荐等 P0 能力 |
| 建议 | 按 §7 的 Phase 1 → 3 分阶段落地；Phase 1 涉及 API/DB/开放契约变更，需人工评审后再生成 SDK |

一句话：**当前实现约为红果"创作者后台"的一个子集，而不是红果 App 本身。** 把它直接当作红果对标产品会得出错误结论。

## 2. 红果短剧功能基线（公开资料）

红果短剧（抖音/番茄系）的核心形态：竖屏免费短剧 + 广告变现，强调"打开即刷、一次看全集"。公开资料归纳如下（来源见 §9）：

| 能力域 | 红果基线能力 |
| --- | --- |
| 发现 | 首页推荐信息流、上下滑切换、分类频道、探索/片库、热门榜单（热播/新剧/漫剧等）、搜索（剧名/演员/题材） |
| 剧集 | 剧目 → 分集；任意选集、上一集/下一集、自动连播、预缓冲、小窗/画中画、投屏/TV |
| 播放器 | 竖屏、倍速、清晰度切换、横竖屏、网络自适应、断点续播 |
| 用户资产 | 收藏、观看历史、播放进度、跨端同步、推荐依据设置、下载/离线 |
| 互动 | 评论、分享、弹幕（TV 版） |
| 账号 | 抖音授权/手机号登录、多端登录 |
| 商业化 | 免费观看 + 广告变现；曾有金币激励/提现（官方公告 2026-11 起逐步下线，2026-12-31 前全量下线） |
| 内容供给 | 网文 IP 改编、制作方保底/分账、审核后上线、独家首发 |
| 合规 | 内容审核、网络剧片相关资质/备案、未成年人保护、隐私合规 |

## 3. 当前实现清单（仓库证据）

### 3.1 API 契约（`apis/open-api/drama/drama-app-api.openapi.json`）

| 方法 | 路径 | Operation |
| --- | --- | --- |
| GET | `/app/v3/api/system/health` | `systemHealth.retrieve` |
| GET | `/app/v3/api/system/ready` | `systemReady.retrieve` |
| GET | `/app/v3/api/episodes` | `episodes.list` |
| POST | `/app/v3/api/episodes` | `episodes.create` |
| GET | `/app/v3/api/episodes/{episodeId}` | `episodes.retrieve` |
| PATCH | `/app/v3/api/episodes/{episodeId}` | `episodes.update` |
| DELETE | `/app/v3/api/episodes/{episodeId}` | `episodes.delete` |
| POST | `/app/v3/api/episodes/{episodeId}/publish` | `episodes.publish` |
| GET | `/app/v3/api/episodes/{episodeId}/assets` | `episodeAssets.list` |
| POST | `/app/v3/api/episodes/{episodeId}/assets` | `episodeAssets.create` |

特征：单一扁平 `Episode`（`title`/`synopsis`/`status`），按租户列出**所有状态**；没有"剧目/季/分类/标签/演员/封面/排序权重/可见性"模型。

### 3.2 数据模型（`database/migrations/postgres/`）

- `episodes`：`id`、`tenant_id`、`title`、`synopsis`、`status`、时间戳。
- `media_assets`：`episode_id`、`kind`（cover/video/audio/subtitle）、`drive_uri`、文件名/类型/大小/状态。
- 无 `series`、`seasons`、`genres`、`cast`、`viewer_progress`、`favorites`、`history`、`comments`、`ad_events`、`play_sessions` 等表。

### 3.3 客户端（`apps/sdkwork-drama-pc`、`apps/sdkwork-drama-h5`）

已实现：IAM 登录/组织选择/会话持久化、剧集列表（游标分页 + 状态筛选）、新建/编辑/发布/删除、媒体列表与代理上传（64 MiB/类型校验）、加载/空/错误/校验状态、PC 工作台与 H5 全宽移动壳、深链。

未实现：信息流、搜索、榜单、剧目详情（series）、竖屏播放器、选集/连播、进度续播、收藏、历史、评论、分享、广告位、离线下载。

### 3.4 其他

- IAM：已接入 `@sdkwork/iam-app-sdk`（密码登录、组织选择、会话刷新/注销）。
- 运行时：`/runtime-env.json` + `SDKWORK_RUNTIME_ENV`、token 持久化、PC/H5 独立构建与拓扑接入。
- Flutter/小程序：仅有脚手架壳，未接业务。

## 4. 差距矩阵（对标红果）

状态：✅ 已实现；🟡 部分/需增强；❌ 未实现；🔒 需产品/架构评审（契约/数据模型变更）。
优先级：P0 = 商业化最小闭环；P1 = 体验/增长；P2 = 差异化。

| 能力 | 红果 | 当前 | 状态 | 优先级 | 所需工作 |
| --- | --- | --- | --- | --- | --- |

| 搜索 | 剧名/演员/题材 | 无 | ❌ | P0 | `q` 搜索 API + 索引（Postgres trigram/全文）；PAGINATION_SPEC 约束 |

## 5. 商业化就绪度

| 维度 | 现状 | 商业化最低要求 | 结论 |
| --- | --- | --- | --- |
| 内容供给 | 仅作者可创建单集 | 剧目库、版权/授权、审核上线、分账 | 未就绪 |
| 播放与分发 | 无播放地址/播放器 | CDN/HLS、防盗链、多码率、播放质量 | 未就绪 |
| 用户增长 | 无推荐/搜索/榜单 | 发现-观看-留存闭环 | 未就绪 |
| 变现 | 无广告/支付 | 广告 SDK/SSV、频控、结算；或订阅/单集解锁 | 未就绪 |
| 数据 | 无埋点 | 播放/留存/ARPU/广告归因 | 未就绪 |
| 合规 | 无内容资质流程 | 网络剧片相关资质/备案、审核、未成年人、隐私 | 未就绪 |
| 运维 | 后端构建当前被 Drive API 漂移阻塞 | 可构建、可观测、可回滚 | 阻塞 |

**判断**：技术上可在现有 IAM/网关/Drive 基础上扩展，但"完整一致 + 商业化"是一个产品级工程，不是一次回归修复。需要单独立项、契约评审与内容/商务资源。

## 6. 本轮回归检查结果

- PC/H5：`tsc --noEmit` 通过；各 10 个服务单测通过；`build:prod` 通过。
- 仓库门禁：15 项标准检查全部通过（topology、manifest、browser runtime/build、docs、workspace、pnpm script 等）。
- 结论：**作者侧已实现功能无回归**；但这不能证明"与红果一致"，因为消费侧功能本就不存在。
- 已知阻塞：`sdkwork-drive` API 漂移导致 `cargo check/test` 与 `pnpm dev` 失败（本仓库 Rust 代码未改动），商业化前必须先修复。

## 7. 建议的分阶段落地

### Phase 1 — 消费侧 MVP（P0，建议先做）

范围：H5 竖屏看剧闭环 + 最小内容目录。

- 数据模型：`series`、`series_episodes`（或 season/episode 关系）、`categories`/`tags`、`series_cast`、`viewer_progress`、`viewer_favorites`、`viewer_history`、`play_sessions`。
- API（需评审）：`GET /catalog/series`（分页/分类/排序）、`GET /catalog/series/{id}`、`GET /catalog/series/{id}/episodes`、`GET /catalog/search?q=`、`GET/PUT /viewer/progress/{seriesId}`、`GET/POST/DELETE /viewer/favorites`、`GET /viewer/history`、`POST /playback/sessions`（返回签名播放地址）。
- 播放：HLS/MP4 签名地址；H5 播放器（播放/暂停/进度/倍速/清晰度/选集/自动连播/续播）。
- 内容：作者侧发布 → 目录可见；封面/剧集元数据补齐。
- 验收：一个真实剧目可在 H5 被发现→播放→切集→退出→续播；收藏/历史可用；埋点上报播放事件。

### Phase 2 — 商业化闭环（P0/P1）

- 广告：开屏/信息流/激励视频/贴片，SSV 回调、频控、广告位配置；或付费解锁（IAM/支付组件）。
- 数据：播放/留存/广告事件看板与归因。
- 互动：评论、分享；推荐 v1（热度/编辑精选）。
- 合规：内容审核流程、资质备案、未成年人模式、隐私政策与广告合规。
- 验收：可配置广告位并产生可对账的曝光/完播/点击数据；审核后内容才可上线。

### Phase 3 — 多端与规模化（P1/P2）

- Flutter/原生客户端、离线下载、推送、投屏/TV、多端进度同步、应用商店上架。
- 推荐/搜索服务化、CDN 多区域、DRM、灰度与回滚。
- 验收：双端一致播放体验、崩溃/卡顿达标、上架合规通过。

## 8. 需要人工决策/评审

1. **产品方向**：是否把 drama 从"创作者工作台"扩展为"消费级短剧平台"（这会改变 PRD 与 Canon 架构文档）。
2. **契约变更**：Phase 1 的 API/DB 变更需按 `API_SPEC.md`/`DATABASE_SPEC.md` 评审后再生成 SDK（`apis/open-api/` 变更需人工评审）。
3. **商业化模式**：广告变现 vs 付费解锁/订阅；是否复刻金币激励（红果已下线，不建议）。
4. **内容与合规**：剧目版权、审核、备案、未成年人保护、广告资质由业务方提供。
5. **多端优先级**：先 H5 移动 Web，还是直接 Flutter 原生。
